# astrbot_plugin_rss_plus

✨ RSS 订阅增强版：在 [astrbot_plugin_rss](https://github.com/Soulter/astrbot_plugin_rss) 的基础上，
把**翻译功能内置化**，并新增了一个 **WebUI 插件配置页**。

## 相比原版做了什么

### 1. 翻译功能内置化
- 直接复用 **AstrBot 已配置的大语言模型**，不再需要任何第三方 API Key，
  也移除了对 `openai` SDK 的依赖；
- 原来的同步阻塞调用改为 **异步** 调用，不会再卡住 Bot 的事件循环；
- 新增翻译缓存、超时保护、失败兜底与「已是目标语言就跳过」判断；
- 模型可按「指定 Provider → 当前会话模型 → AstrBot 默认模型」的顺序自动选择；
- 触发范围可配置（默认只在 `x.com` / `twitter.com` 链接上翻译，保持原行为）。

### 2. 新增插件配置页
在 WebUI 的插件详情页即可打开「RSS 订阅增强版」页面，里面可以：

- 修改全部推送配置（标题/描述长度、每次条目数、合并转发、文转图、隐藏链接、显示标题）；
- 修改全部图片配置（读取图片、防和谐、每次图片数）；
- 修改全部翻译配置（开关、模型、目标语言、触发域名、超时、温度、缓存、标题翻译、跟踪参数清理）；
- **修改推送文本样式**（「推送样式」页签）：消息模板（分隔线也写在模板里）、正文长度上限，并支持**不保存直接预览**；
- **视频帖开关**（「常规」页签）：视频帖要不要推送封面图和视频播放页链接；
- 查看运行状态：调度器、频道数、订阅数、任务下次执行时间、当前生效的模型、数据文件位置；
- **新增订阅**：可以在页面里直接添加（Feed 直链 或「RSSHub 端点 + 路由」两种方式），
  填推送会话、推送频率、该订阅的图片上限；抓不到频道信息时会明确报错，确认无误可勾选「强制添加」；
- 管理订阅：修改某个会话的推送频率、图片上限或删除订阅；
- 管理 RSSHub 端点：添加/删除；
- 在线测试翻译（会显示耗时与所用模型）。

### 3. 推送文本样式可配置 + 智能换行（v1.3.3 起）
- 推送长什么样（「更新了喵❤」「内容：」「链接：」「---」这些文案、分隔线、整条消息的排版）
  全部由配置里的 `message_style` 决定，**改样式不用再动代码**；
- 换行更智能：句末标点 / 英文句子边界自动断行、英文缩写（`Mr.` `e.g.` `U.S.`）不会误断、
  链接内部绝不换行、结尾的话题标签各自成行、多余空行折叠；
- 超长正文会**优先在句子结束处截断**，不会把一条链接切成两半；
- 默认样式与旧版本排版完全一致，升级后不会有任何观感变化，只有换行更聪明；
- **微博视频帖不再只有干巴巴的文字**：封面图会当作图片一起推送（受图片开关与上限控制），
  视频播放页链接填进 `{video}` 变量；不想要的话在「常规」里关掉「视频帖：推送封面图与视频链接」即可。

### 4. 稳定性修复
- 定时任务 ID 改为 `md5`，避免 Python `hash` 随机化导致重启后任务重复或丢失；
- 数据文件放到 AstrBot 插件数据目录并**原子写入**，旧数据自动迁移；
- 数据文件结构自检，手工改坏 json 也不会导致插件整体起不来；
- RSS 解析、图片下载增加超时/体积上限/类型校验，图片会话复用连接池；
- 危险指令（RSSHub 增删、清空数据）增加管理员权限校验。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/rss rsshub add <url>` | 添加 RSSHub 端点（管理员） |
| `/rss rsshub list` | 查看 RSSHub 端点 |
| `/rss rsshub remove <idx>` | 删除 RSSHub 端点（管理员） |
| `/rss add <idx> <route> <分> <时> <日> <月> <周>` | 通过 RSSHub 路由订阅 |
| `/rss add-url <url> <分> <时> <日> <月> <周>` | 通过 Feed 直链订阅 |
| `/rss list` | 查看当前会话的订阅 |
| `/rss remove <idx>` | 删除订阅 |
| `/rss get <idx>` | 立即获取最新一条 |
| `/rss pic <idx> <数量>` | 单独设置某条订阅的图片数量（0 不发图 / -1 不限 / default 跟随全局） |
| `/rss pic-test <图片链接>`（别名 `/rss picdebug`） | 诊断一张图片为什么发不出去 |
| `/rss translate <文本>`（别名 `/rss tr`） | 用内置翻译测试一段文本 |
| `/rss clear-all` | 清空所有任务与订阅（管理员） |

Cron 表达式为 5 段：`分 时 日 月 周`，例如 `0/30 * * * *` 表示每 30 分钟。
星期取值 `0-6`，`0` 表示星期天。

## 推送文本样式（模板 + 智能换行）

推送消息长什么样，由配置里的 `message_style` 决定。三个地方改都行，保存后立即生效：

1. 插件页面 →「**推送样式**」页签（右边就是实时预览，**不用保存也能先看效果**）；
2. WebUI 的插件配置面板（`_conf_schema.json` 生成的那个表单）；
3. 直接编辑配置文件 `data/config/astrbot_plugin_rss_plus_config.json`。

### 模板变量

| 变量 | 含义 |
| --- | --- |
| `{chan_title}` | 频道名，例如「知任CHS」 |
| `{title}` | 文章标题。**单独占一行时**，如果关闭了「显示标题」或该条没有标题，这一行会整行消失（不会留下空行） |
| `{content}` | 正文（已完成智能换行与长度截断） |
| `{link}` | 原文链接 |
| `{video}` | 视频帖的播放页链接（已去掉 `luicode`/`launchid` 等跟踪参数）；不是视频帖时为空 |
| `{video_cover}` | 视频封面**图片**插在这个位置（单独放一行效果最好）；不是视频帖时整行消失。不写这个变量时封面仍会发，只是位置固定在文字后面 |
| `{pub_date}` | 发布时间字符串 |
| `{feed_url}` | 订阅源地址 |

不认识的 `{xxx}` 会原样保留，不会报错。

> **一行里用到的变量全是空的，这一行就整行消失。**
> 因为这条规则，`视频：{video}` 这种写法在普通帖子上会连「视频：」三个字一起消失，
> 不会留下空行或光秃秃的标签；没标题时的 `{title}` 同理。

> **分隔线没有单独的配置项**：默认模板里的 `---` 只是一行普通文字，想换成 `━━━━`、换成 emoji、
> 或者整行删掉，直接在模板里改就行。
> 从 v1.3.3 升上来的配置如果模板里还写着 `{separator}`，会自动替换成分隔线文字（旧配置项有值就用旧值，
> 否则用 `---`），不会把花括号发到群里。

### 默认模板（与旧版排版完全一致）

显示链接时（`template`）：

```text
{chan_title} 更新了喵❤
---
{title}
内容：{content}
视频：{video}

链接：{link}
---
```

其中「视频：{video}」只在视频帖上出现；隐藏链接时用的 `template_hide_url` 默认**不含** `{video}`，
即「隐藏链接」同时也隐藏视频链接，需要保留的话把 `视频：{video}` 加到那份模板里即可。

隐藏链接时（`template_hide_url`）：

```text
{chan_title} 更新了喵❤
---
{title}
内容：{content}
---
```

想换说法直接改文字即可，例如把「更新了喵❤」改成「有更新啦」，或者把两条 `---` 删掉。

### 封面图放哪儿：`{video_cover}`

封面图是**独立的一条消息组件**，所以位置可以随便定：在模板里把 `{video_cover}` 单独放一行，
封面图就插在那一行（消息会按它切成「文字 → 图 → 文字……」几段）：

```text
{chan_title} 更新了喵❤
---
{title}
内容：{content}
{video_cover}
视频：{video}

链接：{link}
---
```

效果：

```text
央视新闻 更新了喵❤
---
中秋国庆档片单
内容：中秋国庆超20部中外影片上新……
🖼 ← 封面图在这里
视频：https://video.weibo.com/show?fid=1034%3A…
链接：https://weibo.com/2656274875/Rjjrm6YZi
---
```

- 想放在开头就把它写在最前面，想放在结尾就写在最后一行，位置完全由你决定；
- **不写 `{video_cover}`**：封面照旧会发，只是位置固定在文字之后、作为第一张图（旧行为，升级无感）；
- 不是视频帖时这一行会整行消失，不会留下空行；
- 插件页面「推送样式 → 样式预览」里会把封面位置标成 `🖼（视频封面图会插在这里）`，
  并提示你的模板里到底有没有写这个变量。

### 配置项一览

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `template` | 见上 | 显示链接时使用的整条消息模板（分隔线也写在里面） |
| `template_hide_url` | 见上 | 开启「隐藏链接」后使用的模板（里面不写 `{link}` 就不会发链接） |
| `smart_break` | `true` | 智能换行总开关，关掉后只做空白清理 |
| `hashtag_own_line` | `true` | 结尾处一连串的 `#话题#` 各自占一行 |
| `collapse_blank_lines` | `true` | 连续空行最多保留一个 |
| `max_content_length` | `200` | 正文长度上限，`0` / `-1` 表示不限制（只受「描述最大长度」约束） |
| `pic_error` | `图片链接读取失败` | 图片抓取失败时显示的提示文字 |
| `pic_error_detail` | `图片处理失败: {url}` | 处理图片抛异常时显示的提示，`{url}` 为图片地址 |

### 智能换行规则

`smart_break` 打开时，顺序如下：

1. **句末标点断行**：内置的 `。！？!?…`（**固定规则，没有配置项**）之后换行，
   且不会在标点后残留空格；
2. **英文句子边界断行**：`.!?` + 空格 + 大写字母视为一句结束，但 `Mr.` `e.g.` `U.S.`
   这类缩写、单个字母缩写以及 `3.14` 这种小数不会误断；
3. **链接保护**：`http(s)://` 与 `www.` 开头的链接会先被"保护"起来，
   绝不在链接内部换行（旧版本会把 `...#frag` 拆成两行，正文里的长链接也会被截断打散）；
4. **话题标签**：结尾的一串 `#话题#` 各自单独成行；夹在句子中间、后面还有正文的标签保持原样；
5. **收尾整理**：折叠多余空行、清掉行尾空格与首尾空白。

### 截断规则

超过 `max_content_length` 时会按下面的顺序找一个体面的断点，再补 `...`：

1. 如果断点落在某条链接内部 → 直接退到该链接之前，**绝不切断链接**；
2. 否则停在本句最后一个句末标点之后；
3. 再否则退到最后一个空格 / 换行处；
4. 都不合适才硬截。

> 提示：截断发生在「智能换行之后」，所以 `200` 这个长度是按最终消息（含换行）算的。

## 视频帖：封面图与视频链接

RSSHub 的微博视频帖在正文末尾会渲染成这样一块：

```html
<video controls="controls" poster="https://tvax2.sinaimg.cn/orj480/xxxx.jpg">
  <source src="https://f.video.weibocdn.com/xxxx.mp4">
  <p>视频无法显示，请前往<a href="https://video.weibo.com/show?fid=1034%3A123&luicode=...">微博视频</a>观看。</p>
</video>
```

- **封面图**优先取 `poster`（来自微博 API 的 `page_info.page_pic`，livephoto 同理），
  插件会在删掉整块 `<video>` 之前把它取出来；
- **视频播放页链接**取自块里的 `<a href>`，并会自动去掉 `luicode`、`launchid` 等跟踪参数，
  只留 `fid`，填进模板变量 `{video}`；
- 视频文件本身**不会**被下载推送（只发封面图），因为微博视频直链带时效签名，而且体积很大；
- **接口兜底**：如果 RSSHub 没给出 `poster`（例如订阅地址带了 `displayVideo=0`、RSSHub 版本较老、
  视频没有 mp4 直链、或者正文里只剩一个视频链接），插件会拿视频号 `oid` 去调
  `https://h5.video.weibo.com/api/component` 换一张 `cover_image` 回来——
  这个接口**不需要 cookie**，8 秒超时，结果（含失败）会缓存，失败就只发视频链接、不影响推送。
  同一条视频在多个订阅/会话里只会请求一次。

开关在「常规」页签：**视频帖：推送封面图与视频链接**（配置项 `show_video_info`，默认开启）。

| 状态 | 封面图 | 视频链接 | 正文 |
| --- | --- | --- | --- |
| 开启（默认） | 随消息发出，**不受「读取图片」总开关限制**，封面优先、不会被图片上限裁掉 | 填进 `{video}`，默认模板里显示为 `视频：<链接>` | 「视频无法显示…」这类噪音文案照旧清掉 |
| 关闭 | 不出现（等同旧版行为） | 不出现 | 同上，和开启时完全一致 |

封面图和正文图片是两条独立的通道，组合起来是这样：

| 视频帖开关 | 读取图片 | 图片上限（全局或该订阅） | 实际发出 |
| --- | --- | --- | --- |
| 开 | 关（默认） | 任意（含 `0`） | **只发封面** |
| 开 | 开 | `0` | **只发封面**（正文图片不发） |
| 开 | 开 | `3` | 封面 + 3 张正文图（写了 `{video_cover}` 时封面插在模板指定位置） |
| 开 | 开 | `-1` | 封面 + 全部正文图 |
| 关 | 开 | `-1` | 只发正文图（旧行为） |
| 关 | 任意 | `0` | 什么都不发 |

注意：

- **封面不占「每次最大图片数量」的名额**，也完全不受它影响：上限是 `3` 时发出的是「封面 + 3 张正文图」，
  上限是 `0` 时仍然发封面（`0` 的语义是「正文图片不发」）；
- 连封面都不想要，就关掉「视频帖：推送封面图与视频链接」开关——那是控制封面的唯二开关之一
  （另一个是模板里的 `{video}`，它管的是链接文字）；
- 只想发封面、不想发正文图，就不要开「读取图片」，或者把图片上限设成 `0`；
- 日志里每次解析到视频帖都会打一行 `rss: 视频帖 <链接> 封面 N 张、播放页 <链接>`，
  用来确认究竟是「源里没有视频块」还是「图片没发出去」；
- 隐藏链接（`is_hide_url`）时用的是 `template_hide_url`，默认不含 `{video}`，也就是**同时隐藏视频链接**；
  想在隐藏链接时也保留视频链接，把 `视频：{video}` 加到那份模板里；
- 极少数视频（RSSHub 拿不到任何 mp4 直链时）根本不会输出 `<video>` 块，这种就既没有封面也没有视频链接，
  插件无能为力；被转发的视频取的是被转发微博的视频，规则一样；
- 订阅地址不要写成 `/weibo/user/<uid>/0`——那是 RSSHub 的 `displayVideo=0`，源里直接就没有视频块了；
  不带参数的 `/weibo/user/<uid>` 默认就会输出视频块。

## 在插件页面里新增订阅

「订阅管理」页签顶部就是新增订阅表单：

| 字段 | 说明 |
| --- | --- |
| 订阅源 | 两种模式：`Feed 直链` 填完整 URL；`RSSHub 路由` 选一个已添加的端点再填路由（如 `/weibo/user/123456`） |
| 推送会话（umo） | 必填，格式 `平台:类型:会话ID`，例如 `aiocqhttp:group:123456789`；输入框会自动列出已有订阅里的会话供选择 |
| 推送频率（cron） | 必填，5 段：分 时 日 月 周，如 `0/30 * * * *` |
| 图片上限 | 可留空（跟随全局），也可填 `0`/`-1`/`n` |
| 强制添加 | 抓不到频道信息时（网站被墙、不是 RSS、需要鉴权等）仍要添加 |

添加前会做这些校验（等价于聊天指令，但提示更详细）：

1. `umo` 必须是 `平台:类型:会话ID` 三段格式——否则定时任务根本发不出去；
2. 地址必须是 http/https 链接或 IP；
3. cron 必须合法；
4. 会真实抓取一次该地址，并确认内容**确实是 RSS/Atom/RDF**（根节点或存在 `item`/`entry`/`channel`）
   且能解析出频道标题；否则报错并拒绝，避免把普通网页当成订阅源加进去。勾选「强制添加」可跳过这一条。

## 每条订阅独立的图片数量限制

图片相关配置分两层：

- **全局默认**：`图片` 页签里的「读取图片」「每次最大图片数量」，对所有订阅生效；
- **单个订阅覆盖**：在插件页面「订阅管理」页签，每条订阅后面都有「图片上限」输入框，可以单独填写：

| 填写内容 | 效果 |
| --- | --- |
| 留空 | 跟随全局默认 |
| `0` | 该订阅不发送正文图片（视频帖封面图仍会发） |
| `-1` | 该订阅正文图片数量不限制 |
| `n`（1~50） | 该订阅最多发送 n 张正文图片 |

> 这里的数量只管**正文图片**。视频帖的封面图不占名额、也不受 `0` 影响，
> 它由「常规」页签里的「视频帖：推送封面图与视频链接」开关控制。

> 显式填写了数字（包括 `-1`）时，表示「这条订阅需要图片」，即使全局的「读取图片」开关是关闭的，也会为该订阅读取图片。
> 每条订阅、每个会话互不影响；同一订阅下的不同会话也可以各自设置。

在聊天里也可以用指令修改：`/rss pic <序号> <数量>`，序号来自 `/rss list`（列表里会显示当前图片设置）。

## 微博视频噪音会被自动清理

> 视频帖的**封面图**和**视频播放页链接**现在会被单独保留下来（见
> [视频帖：封面图与视频链接](#视频帖封面图与视频链接)），下面清理的只是噪音部分。

微博（RSSHub 路由）里的视频帖，正文通常长这样：

```html
<a href="https://weibo.com/tv/show/123"><img src=".../timeline_card_small_video_default.png"/></a>
视频无法显示，请前往<a href="...">微博视频</a>观看。
<video src="https://f.video.weibocdn.com/xxx.mp4"></video>
<a href="https://weibo.com/123">知任CHS的微博视频</a>
```

推送时这些都会被清掉：

| 噪音 | 处理 |
| --- | --- |
| `<video>` / `<audio>` / `<iframe>` / `<source>` 等媒体标签 | 整块删除 |
| 指向 `weibo.com/tv`、`video.weibo`、`/video/` 的链接 | 整块删除（连同里面的播放图标图片） |
| 文本「xx的微博视频」「视频无法显示，请前往微博视频观看。」「网页链接」「▶」 | 正则清理（链接先被删时会自动兼容缺字的情况） |
| 播放图标类图片（`timeline_card_small_video`、`video_default`、`play_icon` 等） | 不作为图片发送 |
| 标题被清空（例如整条就是「知任CHS的微博视频」） | 回退为「无标题」 |

标题与正文都会清理，且**在翻译之前**完成，所以译文里也不会再出现这些内容。

## 图片读取失败的排查

推送里出现「图片链接读取失败」时，图片本身**并不是没抓下来就一定有问题**：可能是防盗链、可能是图床返回了网页、也可能是地址写法不规范。本插件已经把这些情况都做了兼容，并把失败原因写进日志（`astrbot` logger）。

页面「状态 / 工具」页签里有 **图片链接诊断**：粘一条图片链接，会显示

- HTTP 状态码、Content-Type
- 实际探测到的文件格式（按文件头魔数判断）
- 字节数、PIL 解析出的尺寸与模式
- 失败原因（例如「返回的是网页而不是图片」「请求超时」「图片超过 12MB 上限」）

聊天里也可以用 `/rss pic-test <图片链接>` 得到同样的信息。

### 微博图片（sinaimg）实测结论

2026-09 实测 `https://wx4.sinaimg.cn/mw690/....jpg`：

| 请求头 | 结果 |
| --- | --- |
| 不带 Referer | **403**，返回 HTML |
| `Referer: https://wx4.sinaimg.cn/`（图片自身域名） | **200**，image/jpeg |
| `Referer: https://weibo.com/` | **200**，image/jpeg |
| `Referer: https://example.com/` | **403** |

所以微博图**必须带 Referer，而且不能是无关域名**；插件第一次就会带上图片自身域名的 Referer，因此微博图属于「首次尝试即成功」，不需要重试。

其他站点如果只认自家 Referer，会自动退到第二级，内置映射包含：
微博/sinaimg、pixiv/pximg、知乎/zhimg、B站/hdslb、豆瓣/doubanio、微信公众号/qpic、
淘宝/alicdn、小红书/xhscdn、Twitter/twimg、头条/byteimg、百度/bdimg 等。

抓图逻辑的兼容点：

| 情况 | 处理 |
| --- | --- |
| 图床返回 `application/octet-stream` 等非 image/* 类型 | 改用**文件头魔数**识别，是真图就正常发送（旧版会误杀） |
| 完全没有 Content-Type | 同上，按内容判断 |
| 防盗链导致 403 | 三级 Referer 策略：①图片自身域名 → ②该站点官方域名 → ③不带 Referer，依次重试 |
| 200 但返回的是防盗链 HTML 页面 | 同样视为失败，继续换 Referer 重试 |
| `//host/a.jpg` 协议相对地址 | 自动补成 `https://` |
| 相对路径 `/img/a.jpg` | 按该条目的链接自动补全 |
| 地址里带 `&amp;`、空格、中文 | 自动反转义 / URL 编码 |
| `data:image/png;base64,...` 内联图 | 直接解码，不联网 |
| 懒加载 `<img data-src=...>`、`srcset` | 依次尝试 `data-src`/`data-original`/…/`srcset`/`src` |
| 1x1 占位图、`loading.gif` 等 | 自动跳过 |
| 返回 HTML/SVG、PDF 等 | 拒绝并给出明确原因，不会当成图片发出去 |

## 已知坑：图片「上半部分正常、下半部分是灰块」

这是**图片数据被截断**的典型表现（JPEG 解码器会把缺失的行填成灰色）。

原因曾经是：为了限制单张图片体积，代码写成了 `await resp.content.read(MAX + 1)`。
aiohttp 的 `StreamReader.read(n)` 在 `n > 0` 时**只返回当前缓冲区的一个分片**（通常 64KB），
并不会读满 n 字节 —— 于是大图只下载了一部分就交给平台发送，下半部分就成了灰块。

现在的实现：

- 用 `async for chunk in resp.content.iter_chunked(64 * 1024)` 一直读到 EOF，同时做 12MB 上限保护；
- 如果响应带 `Content-Length`（且未压缩），长度对不上直接判定「传输被中断」，不会发半张图；
- 发送前做**完整性校验**：JPEG 必须有 EOI(`FFD9`)、PNG 必须有 IEND、GIF 必须有结束符，
  不完整就换 Referer 重试或报出明确原因，绝不把灰块图发出去。

   └─ settings/            # WebUI 插件配置页

## 安装

1. 把本插件目录放到 AstrBot 的 `data/plugins/` 下；
2. 在 WebUI 插件页重载插件（新增/删除 `pages/` 目录后必须重载一次）；
3. 打开插件详情页 → 进入「RSS 订阅增强版」页面开始配置。

> 插件页面需要 AstrBot 支持 Plugin Pages（`astrbot.api.web`）。
> 如果你的版本不支持，插件仍然可以通过指令正常使用，配置也可以继续用
> WebUI 的插件配置面板（`_conf_schema.json`）修改。

## 翻译说明

- 翻译默认**只在命中「需要翻译的域名关键词」时触发**，默认值为 `x.com`、`twitter.com`；
  把关键词清空即表示翻译所有订阅内容。
- 若指定的模型不可用，会自动回退到会话模型 / 默认模型；全部失败时保留原文推送。
- 相同内容会命中翻译缓存，不会重复消耗 token。
